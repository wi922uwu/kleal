# Личность = id, а не имя

**Человек в Kleal — это строка `users` с постоянным `id`.** Имя — подпись для показа. У двух людей
оно совпадает, и это норма: анкета хранит имя без фамилии, «Иван» и «Анна» встречаются десятками.
Решение владельца, 26.09.2026: «не надо по имени».

Кто прислал запрос, решает **сессия**, а не поле в теле: `Bearer` → аккаунт → его строка → `id`.
Всё, что принадлежит человеку, хранит `id`, и вопрос «чьё это» решается сравнением `id`.

## Почему

26.09.2026 новый аккаунт «Иван» открыл «Мою активность» и увидел интенты трёх других «Иванов».
Там было три поломки сразу:

- таблица `users` держала первичный ключ по имени, и регистрация тёзки upsert'ом затирала анкету
  прежнего;
- интенты, заявки, переписка и планы хранили владельца строкой-именем, поэтому у всех тёзок они
  были общими;
- без токена по одному имени отдавались чужие входящие, переписка и планы (`threads?self=Иван`).

## Как устроено: сервер

| слой | что держит личность |
|---|---|
| `users` (Postgres) | PK `id`; `name_key` — обычный индекс. `db.save_user/delete_user` работают по `id`. |
| аккаунт (`accounts.json`) | `person_id` = id своей строки; строка знает владельца полем `owner`. |
| `shared/kleal_auth.py` | `caller_person(handler)` → `{id, name}` по сессии: owner → person_id → старая строка без владельца с уникальным именем. |
| onboarding | профиль, правка, удаление — только своя строка по сессии (`my_profile_row`); `body.name` игнорируется. |
| matching | в начале каждого запроса `_whoami` кладёт `self._pid`; ручки берут «кто я» только из него. |
| admin | карточка, пауза/верификация, бан, ответ модератора, стирание учётки — по `id` (`_row_for`); по имени только однозначно, для тёзок страница показывает выбор. |
| buddy | в `/launch` передаёт матчингу `Authorization` того, кто пришёл (`_post(..., auth=)`). Остальные поиски приложение делает само, прямо в матчинг. |

**Хранилище матчинга хранит id** во всех полях-людях: `from/to/frm/who/by/owner/host/guest/other/
with/…_by/about/members[].name` и в ключах словарей «человек → что-то» (responses, live, sides,
votes). Список полей — `_PERSON_KEYS` в `services/matching/app.py`.

**Подпись появляется только на выходе.** `send_json` пропускает ответ через `_humanize`: вместо id
ставит имя, а рядом кладёт `<поле>_id` (у поля `name` в списке людей — `id`). Приложение получает
то же, что раньше, и сверх того id.

**Собеседник** приходит полями `<поле>_id`: `to_id`, `with_id`, `who_id`, `name_id`, `to_ids`.
`_peer(id, name, me, gid)` принимает подпись без id, только если по ней однозначно находится один
человек:

- во всём пуле;
- или, для действий внутри уже существующей связи (`related=True`: сообщение, прочтение, план,
  карточка собеседника, решение по участнику группы), среди тех, с кем `me` уже связан
  (`_counterparts`).

Первый контакт (приглашение, зов в группу, блок, жалоба из выдачи) по связям тёзок не разводит
никогда. Иначе приглашение новому «Ивану» ушло бы старому, с которым уже есть переписка.
Неоднозначно — отказ `AMBIGUOUS_PERSON`, никого не найдено — `UNKNOWN_PERSON`.

**Без сессии** можно действовать только:

- ботом: строка без владельца с уникальным именем (посев, эмулятор жизни);
- временной личностью `anon:<имя>`, если строки с таким именем нет вовсе (смоуки, тесты).

Назваться человеком с аккаунтом без его токена нельзя.

**Перевод старых записей** делается один раз при старте (`_migrate_identity_v2`, отметка
`SESSION["_identity"]["v"] = 2`). Прежние значения лежат в `SESSION["_premig_v2"]`. Тёзки
разводились «по ближайшему входу», и каждый такой выбор записан в журнал строкой
`[identity] тёзки, выбран…`. Боевой перевод 26.09 15:54 UTC дал 12 514 записей, 17 выборов, 5 записей
осталось именами (их не видит никто). Разбор затёртых анкет и старых интентов делает
`tools/identity_repair.py` (report / migrate / plan).

## Как устроено: приложение

Всё живёт в `kleal-app/src/api.ts`:

- `Peer = string | {name, id}` — собеседник в любую обёртку (`message`, `thread`, `propose`,
  `block`, `report`, `person`, `planPropose`, `plans`, `threadRead/End`, `group.invite/approve/
  remove`). Строка допустима там, где id ещё не проведён, но это долг, а не норма.
- `pidOf(row, field)` — id человека из строки ответа.
- `isMe(name, id, meName)` сравнивает по id, когда тот известен с обеих сторон; без id — по имени,
  как раньше.
- `ensureMe()` узнаёт свой id из `/api/onboarding/profile`. Экраны, где «моё» решается
  сравнением, зовут его при открытии. При смене входа (`setSession`) id сбрасывается.
- В переходах собеседник едет парой параметров `who` + `who_id`: разговор, план, карточка
  человека. Если экран открыли без `who_id`, разговор берёт id из первого ответа сервера.
- Кэши приглашений (`src/invites.ts`, `src/ginvites.ts`) держат ключ `id:<id>`, а имя — только
  у строк без id.

## Как писать новый код

- Своя личность — только из сессии: `self._pid` в матчинге, `caller_person` в остальных сервисах.
  `body["self"]`, `body["from"]`, `?self=` — не личность.
- Храни id. Имя в хранилище — только копия для показа, рядом с id.
- Сравнивай id. `_norm_name(a) == _norm_name(b)` про людей — ошибка, кроме показа.
- Новое поле-человек в хранилище добавляй в `_PERSON_KEYS`, иначе оно уедет в приложение сырым id.
- В приложении собеседник — `Peer` с id, «моё» — `isMe(..., row.<поле>_id, me)`.

Плохие признаки в ревью: `name_key` как ключ, `.lower() == me`, `x.name === me`,
`rows[norm(name)]`, `body.get("self")` как «кто я».

## Сторожа

```
python3 kleal-ms/tools/identity_test.py        # тёзки в онбординге и матчинге, без сети (25)
python3 kleal-ms/tools/identity_http_test.py   # то же через HTTP с настоящими сессиями (34)
node kleal-app/tools/identity_test.js          # приложение: тела запросов, isMe, план тёзок (25)
python3 kleal-ms/tools/identity_admin_test.py  # панель модерации: карточка, пауза, бан, ответ (14)
```

Все четыре поднимают своё окружение сами и боевых данных не трогают. Дымовые `*_smoke.py` личность
почти не проверяют: 26.09 они были зелёными, пока подбор несколько часов не узнавал ни одного
интереса (см. ниже).

## Ловушка: `_IDX`

В `services/matching/app.py` имя `_IDX` занято словарём категорий интересов, его читает `cat_of`.
26.09 индекс людей назвали так же, и он затёр словарь при импорте. `cat_of` отвечал `(None, None)`
на любое слово, а все смоуки остались зелёными. Сейчас индекс людей называется `_PEOPLE`. Перед
новым глобальным именем в этом файле (11 тыс. строк) проверь его:

```
grep -n "^ИМЯ\b"
```

## Что ещё по имени

- Журналы движка (`_proposals`, `_exposure`, `_outcomes`, feedback) ведутся по имени кандидата.
- Реакции в ленте подсвечиваются «моими» по имени (сервер уже отдаёт `r_ids`).
- Локальные настройки списка переписок (mute, архив) на устройстве держат ключ по имени.
