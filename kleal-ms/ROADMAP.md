# Kleal — технический план до прод-версии

## Где мы сейчас

**Бекенд — восемь сервисов, работает.** 73 эндпоинта, 382 проверки зелёные на живом стенде,
602 профиля в сторе. Реальная доставка между аккаунтами: приглашения, чат, планы встреч,
блокировки — всё уходит на сервер, а не живёт на устройстве.

**Матчинг — движок по спецификации.** Ранжирование, жёсткие фильтры (возраст, пол, язык, радиус,
блокировки), объяснение «почему этот человек», лестница расширения запроса.

**Флоу 1:1 — закрыт от начала до конца.** Интент → поиск → кандидаты → приглашение → чат →
план встречи → «уже иду» / «опаздываю» → «состоялась?» → отзыв. Обе стороны, с проверками.

**Группы — бекенд готов, интерфейса нет.** Групповые интенты (батч-приглашения, общий чат,
апрув, удаление с причиной) и групповые планы (подтверждения, встречные предложения,
голосование, замок за два часа до встречи).

**Интерфейс — прототип, 42 экрана.** Отрисован по борду Figma, но в нерабочей для прода форме:
один Python-файл, отдающий HTML со встроенным JS. На Expo он не переносится — переписывается.
Ценность в другом: продуктовые решения по 42 экранам уже приняты, копирайт написан на двух
языках и покрыт тестами. Это самая долгая часть работы, и она сделана.

**Аутентификация: есть в бою, нет в репозитории.** Проверено 2026-08-27.

Прежде здесь стояло «чего нет совсем: аутентификации». Это больше не так — и не так в обе стороны:

- В БОЮ она работает. `POST https://aiopenware.com/api/auth/code/request` отвечает `200`,
  вход по коду на почту, сессии и выход обслуживает онбординг:
  `services/onboarding/app.py:3101` (`code/request`), `:3104` (`code/verify`), `:3107` (`session`),
  `:3119` (`signout`). Приложение ходит туда через `src/api.ts` (`auth.requestCode` / `verifyCode`).
- В РЕПОЗИТОРИИ её нет. Здешний `services/onboarding/app.py` — 2710 строк, а ручка на боксе лежит
  на 3101-й: боевой файл заметно больше и содержит код, которого в git не существует.

То есть блокер сместился: не «написать аутентификацию», а **вернуть написанное в git**. Пока этого
не сделано, любая выкладка из репозитория снесёт живой вход.

## Этап 1. Безопасность и стабильность — 1–2 недели

Всё остальное строится на этом, поэтому идёт первым.

**Аутентификация.** Сейчас любой снаружи может прочитать и переписать чужой профиль, поставить
чужому аккаунту паузу, ответить за него на приглашение. Нужен слой сессий/токенов и проверка
владельца на каждой записи.

**Атомарная запись стора.** Состояние сервера переписывается усечением файла без блокировки.
Убийство процесса в момент дампа — а это штатный шаг деплоя — стирает приглашения, планы,
сообщения и блокировки. Атомарная запись в проекте уже есть в трёх местах, надо применить
и здесь.

**Починка деплоя.** `ops/deploy.sh` везёт 4 файла из 98 пакета движка. Правишь скоринг, деплой
пишет «ok», на сервер не уезжает ничего. Пока это не закрыто, любая другая починка не доезжает.

**Критичные баги из аудита.** Админка при каждой записи навсегда режет интересы человека до
шести (под это подпадает 560 профилей из 602). Тестовые фикстуры не отфильтрованы из живой
выдачи. Пауза пользователя размазана по трём полям, панель и движок расходятся.

## Этап 2. Перенос на Expo — 3–4 недели

**Каркас и дизайн-система.** Навигация, токены (цвета, типографика, отступы уже определены
бордом), базовые компоненты: карточка плана, строка участника, кнопки, листы снизу.

**Экраны 1:1.** Онбординг, главный экран, создание интента, поиск, кандидаты, профиль
кандидата, приглашение, чат, полоса встречи. Копирайт и логика состояний переносятся как есть.

**Экраны профиля и настроек.** Личность, интересы, память агента, безопасность, приватность.

**Экраны групп.** Новое — бекенд есть, рисовать с нуля.

**Сборка и выкладка.** EAS build, тестовые сборки, подготовка к стору.

## Этап 3. Функционал, которого нет — 2–3 недели, параллельно этапу 2

**Группы, слой 3.** Что происходит, когда группа падает ниже кворума, и явная конверсия в 1:1
по взаимному согласию.

**Группы, слой 4.** Лимиты Free/Plus. Отдельно: ограничения безопасности не должны сниматься
подпиской.

**Точное время в интенте.** Экран просит дату, время и часовой пояс, интент несёт фразу
(«сегодня вечером»). Для плана точное время уже есть, для поиска — нет.

**Пуш-уведомления.** Сейчас клиент опрашивает сервер каждые три секунды. Для мобильного
приложения нужен настоящий пуш: пришло приглашение, вторая сторона подтвердила план,
собеседник опаздывает.

## Этап 4. Качество матчинга — 1–2 недели

**Выученные категории ни на что не влияют.** `/learn` отвечает успехом, запись сохраняется,
а кросс-словный матчинг внутри выученной категории не работает — ради него фича и делалась.

**Обратное направление не видит расстояния.** При оценке взаимности B→A география теряется,
и на порядок выдачи она фактически не влияет.

**Языковой обмен невозможно провалить.** Кандидат с любым заявленным языком проходит запрос
про конкретный язык и получает обоснование про языковую пару, которой нет.

**Реальные данные вместо синтетики.** Пул из 602 профилей нужно заместить живыми
пользователями и проверить качество выдачи на них.

---

## Этап 5. Готовность к релизу — 1–2 недели

**Требования сторов.** Политика приватности, удаление аккаунта из приложения, модерация
и жалобы (механика уже есть — нужен процесс разбора), возрастной рейтинг.

**Мониторинг.** Логи, метрики воронки, алерты. Сейчас падение видно только по тому, что
кто-то заметил.

**Нагрузка.** Ничего не проверялось под конкурентностью. Нужен прогон до открытия доступа.
